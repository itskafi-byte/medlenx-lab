## BUG — two controls on the medicine card do nothing

**Fixed in `344c27c`.**

**`ui/screens/scan/ScanScreen.kt:249-250`**

```kotlin
onVerifyAgainstMedex = { /* Medex re-check - Step 7 drug index */ },
onReportMisId = { /* escalation queue - Step 9 */ },
```

These are passed into `VerifyMedicinesSection`, which declares them as
`(Int) -> Unit` (`Verification.kt:729-730`) and forwards them to each
`MedicineCard` (`Verification.kt:809`), where `onReportMisId` is attached to a
real `clickable` (`MedicineCard.kt:300`).

So both buttons render and respond to touch, and then do nothing. Kotlin accepts
`{ }` for `(Int) -> Unit` because the implicit `it` is simply unused, which is
exactly why the compiler never complained.

Two reasons this matters beyond the dead tap:

- It breaks acceptance item 4 (verify *all* controls work).
- `HelpScreen.kt:152` tells the user "you can also flag from any medicine card
  after a scan" — the app makes a promise the code does not keep.

**Fix shape:** the plumbing is already there end to end; only the two lambdas are
missing. `onReportMisId` should write an `ErrorReportEntity` (row already has
`correction` / `notes` / `raw`) and confirm with a toast. `onVerifyAgainstMedex`
should re-run the brand through `MedicineMatcher` and refresh suggestions for
that index.

## GAP — the training queue is not persisted

**Partly addressed in `344c27c`** — corrections are now recorded with the
brand as read versus as corrected. The image slice and the queue list/stats
are still missing.

`origin/main` has a human-in-the-loop learning loop that Android lacks:

```
POST /api/training/queue        saves a cropped image slice (base64) + corrected text
GET  /api/training/queue        lists queued examples
GET  /api/training/queue/stats  counts them
```

`training_queue_create` (`app/main.py:1733`) decodes the slice, writes it to
`uploads/training/`, and persists it via `save_training_item`.

Android has **no training table** — the 9 entities are medex, prescriptions,
scanned_medicines, queued_scans, officer_profile, brand_targets, doctor_targets,
doctor_visits, error_reports. `ErrorReportEntity` carries `correction`, `notes`
and `raw`, so a correction is *recorded*, but:

- no image slice is ever saved (the point of the feature — it exists to retrain
  handwriting recognition), and
- there is no queue list or stats surface.

This is acceptance item 3 ("train/learn from corrections"), previously deferred.
It is now confirmed **present on main**, so it is a parity gap rather than an
optional extra.

## GAP — company drill-down

`GET /api/dashboard/company-drilldown` (`app/main.py:818`) →
`get_company_drilldown` (`app/database.py:1159`) returns per-company detail.

Android has `companyShare` (a donut, `AnalyticsViewModel:58`) but no way to tap a
company and drill in. Low severity — the aggregate is there; the detail view is not.

## GAP — DGDA monitor

`GET /api/dgda/monitor` (`app/main.py:1719`) serves the full gazette: banned
list, price-adjusted list, prices.

Android's `RegulatoryData.kt` models `banned`, `prices` and `gazette`, and
`Intelligence.kt` performs DGDA *checks* per medicine — but there is no screen
surfacing the whole monitor list. Low severity.
